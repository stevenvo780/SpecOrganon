# Mandato existente para LogLens

El dueño pidió revisar SpecOrganon, preparar Codex con MCP en Docker para pruebas
reales, buscar una validación autónoma con un proyecto interesante de tamaño
acotado, asignarlo como goal y publicar los resultados en su web existente.
La goal activa mantiene un caso nuevo de nueve fases, pruebas/revisiones reales,
comparación prospectiva N/S/T de varias tareas y dos familias, ablación y release.

La elección de LogLens y de su arquitectura es una decisión técnica delegada a
Codex dentro de ese encargo. Este documento registra el mandato ya recibido;
no afirma que el dueño haya elegido personalmente la arquitectura ni inventa
una aprobación nueva. La política local usa la etiqueta declarativa del dueño
y conserva el juicio técnico separado de conformidad con este mandato.

Alcance autorizado: workspace local, proveedores y cuentas originales existentes,
Docker y web Vercel existente. Conservar fallos y resultados inconclusos; no
copiar credenciales/sesiones, cambiar cuentas para eludir errores, contratar
servicios ni alterar el GOAL raíz, el piloto backup o sus treinta inputs congelados.
Un rechazo o evidencia insuficiente bloquea; completar una fase o un programa
no prueba superioridad metodológica ni el objetivo alimentario de campo.
