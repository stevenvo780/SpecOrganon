# D-099 · puente de dos turnos por suscripción y terna N/S/T

Diseño anterior a nuevas respuestas. El objetivo es comprobar un puente
que devuelve a un modelo resultados numéricos reales y, en T, respuestas
del toolkit. El caso D-E y sus cifras ya están expuestos; no se abre una
reserva. Se conserva D-097 como negativo y no se modifica su candidato.

Una generación produce análisis, informe provisional e ítems; una revisión
de seguridad precede al único replay genérico. T persiste una traza signed
mediante comandos reales y observa compuertas iniciales sin aprobar normas
o fases. Una segunda generación entrega sólo el informe final. Así se evita
confundir una imitación JSON de un ledger con uso real del toolkit.

El plan fija tres brazos independientes S/T/N, Luna medio solicitado, dos
turnos y 360 segundos locales por brazo. No hay sustitución de una celda
fallida o reparación del análisis. Una salida numérica negativa puede
informar el segundo turno si aún queda presupuesto; un modelo, revisión
de seguridad o plazo inválidos detienen la celda. Se conserva todo resultado.

El operador aplica el orden S → T → N y sólo inicia la siguiente celda tras
el terminal de la anterior. El broker impone los límites locales de cada
brazo; **no impone automáticamente ese orden entre brazos**. El recibo
cotejará la cronología registrada y declarará este límite. La inspección
local de seguridad por Codex y su declaración del SHA no son una revisión
humana de calidad, autoridad normativa o custodia independiente.

La información disponible y el replay genérico son comunes. Los comandos
especializados de T son tratamiento y cuentan en su tiempo/uso. La revisión
de seguridad tiene el mismo alcance y no ofrece correcciones de contenido.
No hay topes globales autenticados de tokens, coste o cancelación remota,
cuota Codex fiable, versiones efectivas congeladas, coste humano medido,
contexto interno verificable, panel, réplicas o jueces ciegos. Los dos turnos
son solicitudes CLI nuevas con historia textual conservada, no una sesión
interna cuya continuidad de razonamiento se autentique.

La evaluación numérica será verificable desde el CSV con contrato fijado
antes de los outputs. No se calcula Q ni se elige un ganador. Esta terna
observa un tratamiento inicial, no el efecto del paquete de nueve fases;
no cuenta entre las 24 corridas de prototipos ni demuestra el criterio 4.
El protocolo confirmatorio y el NO-GO del dossier D-E anterior no se cambian.
No se utiliza API facturable ni se interviene en una vivienda.

La exploración de preparación también identificó un auditor bibliográfico
faltante: las 17 claims del pan y siete filas requieren cotejo de valores,
unidades y bases desde pasajes, con negativos de causa aislada. Los nueve
cotejos históricos y la proyección aritmética D-097 no lo sustituyen. Queda
como frente independiente posterior, sin rehabilitar el resultado fallido.

**Aceptación de GOAL: 0/5.** El resultado se añadirá tras revisión, congelación
y ejecución del plan; la presencia de este diseño no demuestra la terna.
